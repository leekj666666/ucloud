# D5 实验计划

问题：在受限动作和小内存环境中，怎样提高证据支持的故障处置质量，并减少不必要的模型上下文与调用。
方法主张：使用共同安全执行器和独立业务验收，比较诊断/证据组织机制；保留有实测收益的最小组合。以下是待检验主张，不是已有成果。

## 主张与判据

| 主张 | 必要证据 | 不允许的解释 |
|---|---|---|
| C1：变更关联、反证和业务验证有助于阻止错误归因及假恢复 | H1 同权限、同预算消融；H2 健康端点/完整业务评分对照；错误提案、执行拦截、转人工和实际恢复分别记录 | 只增加评分检查不能称为恢复能力提升；转人工不算恢复；不能关掉执行器保护制造优势 |
| C2：有界证据组织可以减少上下文/调用且不丢关键依据 | H4 原始有界视图、D4 紧凑视图、候选证据索引；真实 provider usage、证据保留/引用有效率、定位和执行结果 | 字节减少不能冒充 token 减少；补改模型的错误引用不能伪装为原输出正确 |

## 数据与权限

开发 12 例、验证 8 例；以实际机制、目标角色、发布因果及复合干扰区分，不只换随机名字。至少 20 个 D6 留出配置单独封存，本阶段不运行、不调参。故障答案、注入/复原代码及评分器绝不挂入 Agent；只读证据去除 Secret，并使用不含故障名称的随机快照 ID。

固定来源的真实现场快照可用于诊断重放，所有方案获得相同观测权限；重放结果明确标注为诊断实验，不能当作实时自主恢复。端到端结果必须另行在真实故障上验证。B1/B2 若没有执行能力，只报诊断指标；使用共同执行包装时单独标注。

## 必跑实验块

1. M0 预算与评测完整性：硬限制本批真实上游 HTTP 调用 100 次，含失败/重试；SQLite 原子计数，断电保守占用，不允许重启清零。代理拒绝的请求另计、不冒充 provider 调用。真实密钥仅在预算代理，诊断容器仅持有单次运行令牌。无操作/标准修复/表面恢复三种控制实验，共同完整评分器保持 120 秒、120 请求、12 业务不变量、零错误及原延迟/告警门槛。
2. M1 固定基线：B0 明确规则/脚本、B1 同模型单次分析、B2 固定 HolmesGPT 的最小只读工具与共同输出协议、B3 完整 D4 方案。先开发集校准可运行性，验证集随机化顺序进行配对比较。B0 覆盖外明确转人工，B2 包装不宣称上游原生执行功能。
3. M2 H1/H2/H4：一次改一项；H1 消融显式变更/反证提示但保持相同信息权限和必要安全要求；H2a 检测假恢复，H2b 如实现业务反馈再规划须单独测试，未实现或未改善恢复不得混称；H4 比较有界原始、紧凑和索引候选。
4. M3 选择与组合：先报告成功次数/总数及配对胜负。必要安全保护固定开启；验证集收益不确定则保持 D4。成本候选约 20% 降幅仅作筛查，不凑阈值。H5/H6 按剩余失败和预算选择；H7–H9 原计划为瓶颈驱动候选，逐项登记已测/未采纳/待测及原因，不假装全部实现。
5. M4 交付：贡献归属、优化采纳日志、结果表、失败类别、原始轨迹/预算账本、完整本地/远端回归和归档。结论只覆盖实测设置，不承诺泛化或拿奖。

## 执行与预算

用户已明确批准第一批最多 100 次实际模型 HTTP 调用。先做不消耗模型的 M0、隔离和数据采集，再小规模预跑；预跑也计预算。禁止 SDK 重试绕过总额度；每个运行保留限额、超时、退出码、未知 usage 和环境中断。金额缺少已核实价目时保持未知。

预算按阶段分配而非保证正向结果：预跑最多 12 次；主要基线/验证对照优先使用剩余额度；组合和追加重复需在同一上限内安排。随机化调度种子不冒充模型随机种子。正式 D6 每案例重复 3 次、至少 60 次/端到端方案（三方案至少 180 次）原判据不变；D5 预算不足时说明缺口并在需要追加前征求预算，不降低正式次数、不把 D5 筛查当正式留出成绩。

## 风险与停止条件

16GB 主机串行实验；先恢复健康、确认真实故障和日志/告警，再采集。调查故障负载必须在执行/正式窗口前停止并排空。所有失败保存；只有预先定义的基础设施失效可标环境无效，不能把模型失败或超时丢弃。任何禁止动作、验收假阳性、答案泄漏或预算越界立即停止付费/变更，修复后新版本重测。

H2 当前生产实现是独立业务验收，不是已完成的反馈再规划优化。D5 必须分别写清检测收益与恢复收益，不夸大现有能力。

## 开发预跑后的预注册补充（验证集运行之前）

数据设计更正：H1干扰样本必须先注入真实故障，再实施无关服务的RELEASE_ID更新；采集器通过实际ReplicaSet owner、唯一发布值和严格更晚时间校验“最新无关发布”。时间并列不靠随机UID判先后。早期相反顺序样本及一次发布格式校验失败均保留并从正式矩阵排除；相关7个配置重新采集。评测根因记录用显式root_change_index，不能把最后的无关发布当标准答案。

dev_01 预跑使用 B1=1、B2=4、B3=3 次实际 HTTP；仅作可运行性校准，不能据此择优或声称提效。冻结的主系统比较仍为验证8例各 B0/B1/B2/B3，B0免费、B1单次、B2/B3每次最多4次，Holmes最多8步，所有模型调用经同一100次持久预算代理，temperature=0、top_p=1、输出最多8192 token；不支持模型随机种子。

额外使用单次分析的2×2因子比较：B1（neutral+compact）、A_D4_compact、A_neutral_raw、A_D4_raw，验证集每例相同六类现场证据。只在此单次架构内分别归因 prompt 和 view；原始视图完整供给且不截断，紧凑视图使用既有D4转换。Holmes工具内容上限32000字符属于主系统架构，不将跨架构差异全部归因于压缩。短引用 A_D4_alias 为有余量时的候选，不属于必跑2×2矩阵。原始模型错误引用保持原样。

调度种子仅随机化顺序，写入不可变计划后可恢复；缺少的任务单列而不删除，失败不自动重跑。免费B0覆盖开发12+验证8例。默认预留最多4次用于一次实际 B3 现场端到端筛查；额度不足则保留矩阵缺口并征求追加，不能因额度删病例或声称D5全部完成。现场复验和矩阵重放分开，正式D6三次重复的判据不变。

独立设计审查补充：neutral-vs-D4只能称整套提示策略对照。H1单独新增 A_H1_off，与 A_D4_compact 只改变显式“无关发布不能作为因果证据、说明替代解释与不确定性”和reason中的反证要求，其余D4提示逐字不变。所有共同安全、升级、动作边界、证据读取要求保持，准确名称为“显式变更关联与反证推理提示的增量消融”。验证8例全部进入该比较，并预先分有/无干扰子组；不宣称关闭全部因果保护，也不把固定执行边界下的结果夸大为真实误回滚降幅。该补充增加8个单次任务，冻结矩阵共76任务（20规则、56模型诊断），仍受本批100上限约束。
