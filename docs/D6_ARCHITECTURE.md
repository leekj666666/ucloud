# 云巡架构、权限与价值边界

项目解决的问题是：线上业务告警出现后，帮助值班人员关联日志、指标、资源、依赖和发布证据，提出可审查的修复，并验证业务是否真正恢复。不是仅生成故障摘要或任意执行命令的聊天机器人。

## 处理链路

| 环节 | 实际工作 | 失败时处理 |
|---|---|---|
| 发现 | Prometheus/Alertmanager 接入事件，数据库幂等保存 | 重复告警合并；接收失败保留日志 |
| 调查 | 独立诊断身份读取资源、日志、指标、端点与发布 | 工具失败明确记载，证据不充分时转人工 |
| 定位与方案 | HolmesGPT 基于观测生成结构化方案和证据引用 | 无效输出、超时和不支持的动作不能直接执行 |
| 审批与执行 | 操作员批准具体方案；可信基线和当前资源约束实际写入 | 版本冲突拒绝；未知写结果先读回，不能盲重发 |
| 验证与复盘 | 独立业务验证、完整质量窗口、报告导出 | 未满足门槛保持未恢复/转人工，不把清理算成功 |

工作流与动作意图持久化到 PostgreSQL。租约、任务归属、检查点、读回和审计支持进程中断后的明确恢复；停止请求与确认分开，已发出的外部请求不能被假定撤回。

## 四种受限动作

当前策略只允许在受控演练资源上恢复可信基线中的环境配置、Service 端口、副本数和资源配置。模型提出动作不产生权限；执行前绑定 UID、resourceVersion、完整 spec 摘要、证据与旧值，并使用原子前置测试。模型生成的任意 Shell、任意资源删除、未知目标变更均不属于本项目已实现能力。

## 身份与证据隔离

- 诊断侧仅持有受限读身份，没有执行身份；生产 worker 不持有模型 Key。
- 正式评测的真实模型 Key 位于宿主直连代理，诊断镜像只拿代理令牌；故障注入器、参考答案和管理身份不挂载到 Agent。
- 验证器从独立路径经过 NodePort、Service 和 gateway 验证业务；不是让模型自行宣布修复成功。
- 评测器清理仅还原自己注入且 UID/当前值匹配的字段。清理不算 Agent 修复。
- 控制台为本机操作员访问码会话；尚未实现企业 SSO、多租户生产身份和云端 HTTPS 部署。

## 与赛题考核点的对应

| 考核点 | 可展示的项目产物 | 验证证据 |
|---|---|---|
| 场景价值 | 线上故障从发现到修复及复盘的闭环 | 实际演练告警、业务不变量、人工操作反馈 |
| Agent 能力 | 多步调查、工具调用、证据绑定、结构化受限方案 | 原始工具/模型轨迹、失败分类、固定对照 |
| 云原生架构 | 容器、Kubernetes、监控、PostgreSQL 持久化与资源约束 | 权限检查、进程恢复、部署及资源样本 |
| 工程完成度 | 中文指挥台、逐次审批、拒绝/停止、报告与复现 | 真实生产链路验收、CI、用户试用、清洁部署 |
| 成本与性能 | 按真实 HTTP 尝试统计、阶段耗时及已知/未知用量 | 保留失败和重试的账本、完整窗口样本 |

这些是项目与赛题要求的对应关系，不是官方评分结果，也不能承诺奖项。

## 自主贡献与实验选项

HolmesGPT 是明确归属的上游引擎。项目自主实现事件和持久化编排、证据与策略约束、受限执行保护、独立业务验证、人工控制台以及真实对照评测。

H2b 反馈补证和 H5 规则协作保留为可选研究功能，均默认关闭。局部案例的收益不足以证明普遍提升，不能将可选实验功能直接宣传成默认产品增益。正式 D6 测试保持冻结默认系统。

当前是同主机、已知家族、有限服务图的演练系统。尚未证明任意生产故障、复杂企业规模、全自动自治和多集群生产能力；这些边界应在技术文档与答辩中明确说明。
