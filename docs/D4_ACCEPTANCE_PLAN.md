# D4 冻结范围与验收判据

日期：2026-10-25。本文是实施门槛，不代表已通过。依据总计划第 6.6 节和 DEVELOPMENT_WORKFLOW.md 的 D4。

1. 中文操作台：事件列表/搜索/筛选、手动发起、事件影响、当前状态、调查时间线、证据详情、具体修复方案及前后差异、业务验证、用量/费用、报告。桌面与移动端可操作，包含加载、空、断连、无权、冲突和失败状态。
2. 真数据：页面接真实 API/数据库/诊断轨迹，不把示例当实测，不把健康端点当业务恢复，不把未知费用写为零；历史 D1–D3 记录只读兼容。
3. 发起任务：限定服务与 namespace、显式执行模式、持久化幂等创建与操作审计；离线工作器时准确显示排队，不假装已开始调查。
4. 审批：默认人工审批。批准/拒绝绑定 incident、run、action ID 和完整意图哈希；旧方案、错误版本、相反重复决策拒绝；批准不绕过 D3 证据/基线/UID/resourceVersion/spec 原子保护。重启后继续等待或执行同一方案。
5. 停止：请求与确认区分；调查中终止真实诊断进程组；审批前停止不变更；执行请求已发出时先读回，未知结果转人工；停止响应接受后不再发起新的外部写入。验证中停止保留部分窗口，不能报恢复；停止本身不自动恢复已知坏配置。
6. 权限与输入：控制台会话、同源状态修改、凭据不进入前端/导出；所有目标和报告/证据路径绑定当前事件，不接受任意路径/命令；日志文本按纯文本展示。
7. 导出：JSON/Markdown 均支持；包含影响、时间线、证据、计划、审批/停止记录、实际动作、业务验收、未解决项、用量、版本。未完成任务导出明确标记未完成，未知金额保持未知。
8. 真实集成：真实 PostgreSQL 审批竞争与停止/写入顺序测试；真实诊断进程取消；实机浏览器连接 API 完成发起→调查→审批→执行→完整业务恢复；另测拒绝、调查中停止和验证中停止。浏览器覆盖键盘、桌面/移动布局及错误状态，不以 mock 通过代替闭环。
9. 回归与交付：保留 D1–D3 完整测试、依赖锁定、前端类型/构建检查、后端真实 PG 和远端 CI、原始失败/中断、截图/交互记录、源码/镜像证明、完成矩阵与范围说明。D4 判据全通过才标完成；D5 创新增益和 D6 留出/新环境复现仍属后续。

实现依赖：持久化控制/审批 → API 与安全边界 → worker 接入/诊断取消/验证停止 → 操作台 → 实机闭环与异常验收 → 完整 CI/归档。

停止的语义边界：无法撤回已经发到 Kubernetes 的网络请求；用数据库串行控制门保证停止被接受后不再开始新写入，已发送动作必须记录为已应用/未应用/未知并显示人工接管需要。任何实现变更和验收范围调整必须写入进度记录，不隐式删减。
