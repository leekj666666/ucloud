# D5 冻结验收判据

原始范围：docs/plans/DEVELOPMENT_WORKFLOW.md 的 D5、H1–H9 及实验设计。第一批模型预算为用户指定的 100 次实际上游 HTTP 请求，失败/重试计入。

1. 固定 B0/B1/B2/B3 定义、共同模型/预算/只读权限和协议，分别报告诊断及实际恢复，不能凭格式转换或执行功能缺失制造劣势。
2. 建立 12 个开发、8 个验证和不少于20个封存留出配置；有机制/发布关系/复合变体区分，所有标准答案与评测代码在 Agent 文件系统之外。
3. 预算代理在发出上游请求前原子占位并持久化；100次上限不因重启、并发、失败或重试清零。诊断容器不持有真实模型 Key。无网络上游调用的拒绝不混计实际使用；无法确认的在途调用保守占用。
4. 共同外部评分器始终保留完整原门槛。无操作、参考修复和表面恢复控制正确；实际业务验证与诊断重放分开标记。
5. 优先执行 H1/H2/H4 单因素比较，原始输出/工具参数/脱敏证据/usage/执行结果落盘；H2 检测与反馈再规划分开，不把假成功拦截冒充恢复能力提升。
6. H1–H9 均有采纳登记：已测结果/不确定性，或原计划条件未满足而未测的具体原因。基础保护不为了消融关闭。未测/未实现不宣称生效；没有可靠收益可保持D4。
7. 结果保留分母、失败类别、环境无效及重跑关联、配对胜负、时间、模型尝试/token和未知金额；不得只报成功或把重复视为独立案例。
8. 采纳配置通过受影响实机检查、原有完整回归和远端CI；归档源码/版本/原始数据/预算、每文件哈希和已知凭据扫描。
9. D6 正式留出测试及新环境复现仍属后续。每正式案例三次、每端到端方案至少60次未减少。预算不足或关键证据缺失时，D5 保持未完成并明确列出，不擅自降低验收要求。

具体实验顺序见 refine-logs/EXPERIMENT_PLAN.md；本文件是实施判据，不代表已经通过。
