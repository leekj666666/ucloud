# D3 冻结任务与验收计划
日期：2026-10-24。依据 DEVELOPMENT_WORKFLOW.md D3、原计划第6/7节、审计G13及D3明确承接项。本文为待实施判据，不代表通过。

1. 持久化恢复：事件状态、工作流、审计、动作意图/结果原子提交；事件级租约及资源互斥；过期执行者不能提交新状态；重启从持久化检查点续跑。诊断前/后、变更前/后、验证中杀进程，重新采集完整120秒验证，禁止凭旧局部窗口判恢复。
2. 幂等和未知结果：动作具有稳定ID和不可变前置版本；变更前落盘；重启先真实读回区分已应用/未应用/冲突。对同一操作最多一次生效，禁止重复恢复和盲重试。
3. 并发：两个不同目标事件可重叠处理；同一目标排队；重复投递不创建重复动作。数据库连接丢失或租约丢失时停止写入，恢复后对账。
4. 覆盖：配置地址、Service端口、依赖不可用、资源限制四类真实故障，另有无关发布、健康端点正常但业务失败；正常入口、真实告警、动态诊断、限定动作及完整业务验收。不能自主处理的案例真实转人工并创建内部记录，不算自主恢复。
5. 执行：类型化动作、目标/参数/版本绑定、健康基线、状态读回、有界超时；补偿只撤销本次可撤销变更且不能恢复已知坏配置；不安全时停止并转人工，保留证据。
6. 证据：可查发布时间、UID/镜像/配置版本、差异、健康依据；异常原因与最近无关发布区分。资源与延迟告警随故障加入。
7. 隔离：诊断与执行独立身份及最小RBAC；worker容器化；诊断容器不能读取注入脚本/答案/管理员凭据；真实权限允许与拒绝测试。业务数据库物理故障之前隔离控制面数据库实例。
8. 验证：真实服务/PG与进程级故障注入，不以mock代替；120秒、1请求/秒、12次业务不变量、零错误、P95≤max(同负载基线×2,1秒)保持D2标准；所有失败与用量保留。明确预期恢复、预期转人工和评测清理。
9. 交付：锁依赖、本地/远端完整CI、运行源码/镜像/版本证明、完整验收矩阵、失败记录和范围说明。D3必需项全通过方可完成；D4 UI/用户审批取消与D5消融/D6新环境复现保留原阶段。

实现顺序：事务与租约 → 动作对账与可恢复worker → 权限隔离/部署 → 四类故障及干扰/假恢复 → 真实杀进程和并发/异常矩阵 → CI与归档。
当前D2历史验收文件不覆盖。必要实现变更逐项记录，不缩减上述范围。
