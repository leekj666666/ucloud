## 失败、修改与环境维护披露

1. `d4-ui-approve-f7502749c65a` 因驱动缺 PYTHONPATH 在注入前失败，修正调用方式。
2. `d4-ui-approve-bd7016399780` 已真实修复且 120/12/零错误，但故障期请求的延迟告警在正式窗口内触发，按原门槛转人工。D4 改为业务和监控可用、相关严重告警连续清除 15 秒后再进入完整 120 秒窗口；没有删除告警门槛。
3. `d4-ui-approve-0a687bc77a7f` 的模型引用了不存在的证据编号，策略拒绝执行。`d4-ui-approve-3a4c824100e5` 缺匹配日志，策略同样拒绝。未自动改写引用或放宽证据要求。评测器增加调查期间真实请求，方案就绪后停止并排空；请求和实际评测脚本哈希独立落盘，Agent 不读取故障答案。
4. 曾出现 WSL 普通用户/root 启动均 WSAETIMEDOUT；暂停 worker/诊断，通过 Docker 的精确 UID/resourceVersion/自身故障字段条件完成评测清理，保留原清理错误。仅重启 Ubuntu 并恢复安装好的 Docker 集成后复验。该次维护不是 Agent 修复。
5. 后续宿主/Docker 中断使 `6ce6...` 停在 VERIFYING，浏览器退出。恢复数据库/监控/验证器，保留已批准动作；B 验证器旧绑定出现 PermissionError，按原镜像重建。维护记录最初推断了桥接地址变化，复核发现数据库地址本已匹配，已另存更正记录；没有修改业务 Deployment spec。原 run 重新采集完整窗口后才 RESOLVED。
6. 另保留初期诊断夹具引号错误、浏览器审查缓存问题、状态筛选名称缺失，以及非 ASCII 错误码测试把 403 误写成 401 的失败。修复非 ASCII 凭据比较，防止 500。没有减掉旧测试或放宽恢复判据。
7. 权限验收发现 PUBLIC 仍允许连接业务库，移除 PUBLIC CONNECT 并显式授予业务身份；worker 控制行只授予非权限字段的 UPDATE 以供行锁，不能改写模式或清除停止。
