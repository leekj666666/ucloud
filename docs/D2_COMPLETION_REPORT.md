## 本轮失败、修复及变更披露
1. 首次真实验收因部署读取工具失败，缺少证据而转人工；评测器清理恢复。Holmes 的 800 MB 虚拟地址空间限制与 Go kubectl 分配不兼容。诊断读取改为已锁定依赖中的 Kubernetes Python 客户端，原内存上限保留；部署和端点十次受限真实读取通过。
2. 第二次原始 Loki 日志已取到，但重复标签与查询统计导致工具输出超限。完整原始响应继续归档，模型视图去除冗余字段并保留所有已取回日志行、时间戳和证据 ID。未放宽策略证据条件。
3. 第三次完成自主修复与严格验收。三次是开发迭代，不能计算成泛化成功率。
4. 一项竞争测试最初错误假设元数据注解不增加 generation；改为比较竞争操作后的实际版本及 spec，原子拒绝判据不变。
5. 本地 Docker 重启导致数据库/Loki 地址变化，增加环境网络刷新脚本；该维护不算 Agent 修复能力。
6. 重复告警必须在 worker 活着时验收；本地与远端回归从原 21 项扩到 50 项。静态检查中出现的格式问题已修正。
7. 有 1 次额外调查在验收失败清理时被停止，原始 running 工作流保留，并附评测器中断说明，不伪造 Agent 完成状态。自动接管属于 D3。
