# D5 优化与采纳登记

登记日期：2026-10-25。实施与评测状态分开记录；本文件不代表 D5 已验收。原始范围见 [开发流程](plans/DEVELOPMENT_WORKFLOW.md) 的 H1–H9 和 [项目总计划](plans/SRE_AGENT_PROJECT_PLAN.md)。最新实测计数由 D5 结果报告及原始轨迹回填，本登记不固定正在变化的调用数。

目前生产决策：保留 D4 已验收流程和默认逐次人工审批。D5 对照包装器可在专用演练环境中使用共同执行器，不改变控制台默认审批方式。没有可靠的验证收益之前，不将候选配置替换为生产默认。

## 实验类型与共同条件

| 类型 | 本阶段用途 | 可以报告的结果 | 不能据此报告的结果 |
|---|---|---|---|
| 主系统诊断重放 | B0 规则、B1 同模型单次分析、B2 最小 HolmesGPT、B3 D4 提示与紧凑证据的 HolmesGPT 包装 | 输出格式、根因动作代理正确、共同策略可授权性、转人工、调用与已知 usage | 真实业务恢复、完整生产 worker 的吞吐或可靠性 |
| H1 单次增量提示消融 | A_D4_compact 与 A_H1_off；后者仅去除 D4 两句显式因果/反证提示，安全/格式要求、完整观测和视图相同 | 全部8例及预定义有/无干扰发布子组的根因动作代理、无效/被拒提案和同案例配对 | 将固定执行器阻止错误计划解释为 H1 导致实际误回滚下降；从此诊断实验声称真实恢复增益 |
| 单次调用因素实验 | B1（中性提示+紧凑视图）、A_D4_compact、A_neutral_raw、A_D4_raw | 在相同单次架构与同一现场内，分别观察整套提示和证据视图的影响 | 将中性提示与 D4 的整套差别称为 H1 单因素；将单次全部证据输入与多轮 Holmes 调查的差别都归因于一个机制 |
| 新现场端到端 | 重新注入、采证、诊断，再使用共同有界执行核心与独立验收 | 实际动作、策略拦截、完整窗口、根因字段复原、真实恢复 | 将评测器清理或参考修复记为 Agent 恢复；将此包装当成 D4 分布式 worker 全流程验收 |
| D6 正式测试 | 封存配置、新环境复现及正式重复 | 在正式测试完成之后再形成最终指标 | 将 D5 开发/验证集筛查替代正式留出成绩 |

D5 使用 12 个开发配置、8 个验证配置；不少于20个 D6 配置独立封存。本阶段不查看或执行留出配置。已知故障家族内的配置具有相关性，不能当作20种独立未知故障。正式每案例3次、每端到端方案至少60次的原判据保留。

所有付费尝试共用持久化的本批100次实际上游 HTTP 硬上限，失败与重试同样计入。`--reserve-attempts` 只影响调度，不增加预算，也不提前消耗调用。所有组使用同一配置模型、温度0、top_p 1、8192输出上限；不声称模型支持随机种子。诊断容器只有代理运行令牌，不接触真实模型 Key 或评测答案。规则组无网络；基线诊断结果可由共同安全策略评分，不因上游缺少执行能力而直接记恢复失败。

单次输入不截断；Holmes 工具输出有32000字符上限。该差别公开记入协议，跨架构成本和正确率只作系统对照，不用于单因素因果解释。H1 单因素仅比较 A_D4_compact 与 A_H1_off：后者仅去除两句显式因果/反证提示，共同执行协议、必要运行证据、全部读取和安全保护固定。中性提示与 D4 属于整套提示对照，不叫 H1 单因素。

## 停止、采纳和后续更新

调度冻结全部任务，未运行、模型无效输出、工具错误和超时分别保留。格式有效、根因动作代理正确、共同策略允许和业务恢复是不同指标；不支持自动动作的任务只报处置/转人工，不能拿转人工替代根因定位。

本阶段只作小样本计数和同案例配对胜负；缺失项不当作已成功或静默剔除。金额或 usage 缺失保持未知。若本批额度不足，D5 保持未完成并列具体缺口，等待追加预算决定，不擅自减少固定验证集或放松 D6 判据。

真实现场与共同执行器的结果、本地和远端回归、新环境复现分别验收。后续结果报告需逐项回填“测试版本、样本分母、原始路径、收益/退化、是否采纳和理由”；没有可靠收益时继续使用 D4，是允许的实验结论。
