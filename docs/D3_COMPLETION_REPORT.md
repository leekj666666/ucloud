## 失败与调整披露

1. 早期依赖恢复的业务请求通过，但监控尚未就绪，正式验收拒绝通过；增加业务与监控就绪等待，正式门槛未变。
2. 资源故障旧 Pod 仍服务，原业务告警无法触发，补充真实 OOM 告警；另一次故障期请求跨入恢复窗口，按失败保留，改为检测事件后停止并等待故障负载结束。
3. 保留接口断连、空 JSON、参数形状错误等失败。一次 2048 completion tokens 全部用于 reasoning 后没有最终内容，输出上限提高至 8192；调查最多 180 秒/8 步、事件最多 2 次、10 秒持久化退避及整体有界等待保持。未知模型用量不计零。
4. 并发首次启动在服务与监控就绪前采样而失败，新增独立且落盘的前置检查，正式窗口仍记录全部请求并要求零错误。
5. 新增发布历史后运行状态工具输出 10224 tokens 超过原 4800 限制，策略因反证不足拒绝修复。拆成第六个固定只读工具并去重配置，33 个修订全部保留；原失败证据复测两工具约 1892/3667 tokens，低于原限额，四类最终回归复验。
6. 多次 Docker/WSL 停止导致中断，恢复基础设施、刷新桥接地址或评测清理均按环境维护记录，不计自主恢复。历史未完成工作流保留；本轮测试 worker 停止后不会自动重放旧案例。

全部成功、失败、中断索引见 D3_PROGRESS.md，原始目录按独立运行编号归档；不同配置/版本的开发尝试不能拼成同一受控实验。
