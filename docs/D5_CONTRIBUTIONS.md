# D5 贡献与上游归属

本说明以仓库代码为依据区分上游能力、自有工程实现和待验证假设，不作算法原创性认证。最新效果只认 D5 原始记录和结果报告；候选实现与单元测试通过均不等于项目收益已被证实。

## 上游与复用边界

| 组件/机制 | 来源与复用方式 | 本项目声明边界 |
|---|---|---|
| LLM 工具调查引擎 | [HolmesGPT 官方仓库](https://github.com/HolmesGPT/holmesgpt)，固定 commit `4efc18f0cd1fc3e65229bb27d236ed057c6f2424`，同 `docs/HOLMESGPT-COMMIT.txt`；使用其配置、工具调用循环及结果对象，在独立依赖环境运行 | 工具调用 Agent 引擎来自上游；不声称重新发明 HolmesGPT。B2 是本地固定最小工具包装，不代表上游所有默认能力或原生自动修复功能。 |
| 模型推理 | 用户配置的 DeepSeek 官方 API，经 OpenAI 兼容协议/SDK或 HolmesGPT 适配使用 | 未训练或提出自有基础模型。所有组使用同一模型配置，不用模型等级差异替代机制比较。 |
| 云原生与遥测基础 | Docker/Compose、Kubernetes/kind、PostgreSQL、Prometheus/Alertmanager、Loki/Grafana 等已有组件 | 容器编排、数据库、监控和日志组件能力属于相应上游。我们的贡献是针对比赛场景的集成、业务/权限边界和可验收流程。 |
| 常见工程机制 | JSON Schema/结构化输出、持久状态机、幂等、乐观并发、受限动作、哈希证据和独立验证等通用实践 | 这些实践不单独作为原创算法。参赛技术主张是具体组合如何解决线上故障闭环问题，以及对照数据实际支持的增量。 |

依赖继续遵循已有许可证和仓库的许可证归属记录。本文件不替代完整第三方许可证清单。

## 创新验证和效果主张

本项目优先验证两类具体增量：显式变更/运行反证提示能否改善根因动作代理和提案质量，独立业务验收能否发现假成功；证据组织能否在不损失关键依据的前提下降低实际调用或 usage。执行器保护固定开启，提案质量改善不自动意味着实际误回滚减少。H1–H9 的实现、未测条件和采纳规则见 [优化登记](D5_OPTIMIZATION_LOG.md)。

主系统诊断 B0/B1/B2/B3、H1 单次增量提示消融、整套提示/视图2×2因素组合和新现场共同执行器测试分别报告。H1 只比较 A_D4_compact 与 A_H1_off，后者仅去除两句显式因果/反证提示；其余安全、格式和读取要求全部保持。H1 报全部8例及预定义有/无干扰发布子组的同案例配对。中性提示与 D4 的整套差别不能称为 H1 单因素。上游调查能力缺少本项目动作接口时，不把缺接口直接当算法失败；使用本项目共同执行包装时明确标注。

H2a 只检查业务标准，不等于 H2b 反馈再规划。当前没有实现 H2b，不能声称已经靠业务反馈提高自主恢复率。SOP检索、独立模型复核、动态路由、缓存/并行等候选也不得因出现在计划中就写成已完成贡献。

本阶段不作“全新算法”“超过所有成熟项目”“保证拿奖”等表述。验证收益不足或存在回归时保留 D4；D6 正式留出、新环境安装、正式重复与比赛材料仍按原计划另行验收。
